## Assistant

Fastest path: use **EAS cloud build + auto-submit** from the Mac that already has Xcode and your Apple Developer setup. You do not need the sandbox machine for the actual TestFlight upload.

The repo is already set up for this path: [DEPLOYMENT.md](/home/sprite/sprites-rn-manager/DEPLOYMENT.md) documents EAS, and [app.json](/home/sprite/sprites-rn-manager/app.json) already has the iOS bundle id and `usesNonExemptEncryption: false`, so you should not need to fix those first.

Use this flow on the Mac:

```bash
npm install
npm install -g eas-cli
eas login
eas init
eas build --platform ios --profile production --auto-submit
```

A few practical notes:
1. If it’s the first time, `eas` will ask to manage iOS credentials. Let it.
2. For the easiest submit step, use an **App Store Connect API key** rather than Apple ID login.
3. The build happens in Expo’s cloud, so Xcode is mainly needed for the one-time local setup and any debugging if signing goes sideways.
4. When the build finishes, Apple may still take a few minutes to show it in TestFlight as “Processing.”

If you already have an App Store Connect app record and EAS project linked, the shortest version is just:

```bash
eas build -p ios --profile production --auto-submit
```

For a release that only changes JS/TS and not native code, you can still reuse this same pipeline.

what if i want to build locally?

## Assistant

Yes. If you want to build locally, do it on the Mac with Xcode.

Two local paths matter here:

1. **Local dev build for simulator or a connected iPhone**
```bash
npm install
npx expo run:ios
```

2. **Local production archive for TestFlight**
- Generate/open the native iOS project on the Mac:
```bash
npx expo prebuild -p ios
open ios/*.xcworkspace
```
- In Xcode:
  - select the app target
  - set your Team under Signing & Capabilities
  - choose `Any iOS Device` or a real device
  - `Product` → `Archive`
  - in Organizer, `Distribute App` → `App Store Connect` → upload

That is the most direct local TestFlight path if you already have Xcode and the Apple signing setup.

A CLI-only local option also exists:

```bash
eas build --platform ios --profile production --local
```

That still needs the Mac toolchain and signing credentials, and it’s usually less convenient than Xcode for a first pass.

For this repo specifically, I would use:
1. `npx expo run:ios` if you’re just validating the app locally.
2. Xcode Archive + Organizer upload if your goal is TestFlight.
