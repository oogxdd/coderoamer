## Diagnosis (the likely "fix blind" win)

The crash matches a structural gap, not a one-off bug. Incoming output flows through an **async WebSocket callback**:

```
socket.onmessage → appendLog → termRef.write → buffer.write → parser.parse → mutate buffer
```

`TerminalErrorBoundary` only catches throws during **React render/lifecycle**. So:
- a throw in the **parse/mutate path** (runs in the WS callback, outside render) → escapes the boundary → **app crash**
- a **native Skia paint crash** (NaN coordinate, unparseable color) → also uncatchable in JS → **app crash**

That fits your symptom perfectly: the `ls ../` output renders once (you see it), then the next chunk — the shell repainting its prompt — hits one of those paths and hard-crashes instead of showing the "Reload terminal" screen.

## Fixes (containment + hardening)

- **`TerminalBuffer.write`** — wraps `parser.parse` in try/catch; on throw it logs the offending chunk (hex) + cursor/size state and resets the parser, keeping the session alive.
- **`SkiaTerminalRenderer`** — the native-crash vectors: `measureCell` now returns only finite/positive metrics; colors are validated before reaching Skia (`safeColor`); the cursor is clamped into the grid; canvas width/height are guarded; per-row and cursor rendering are each wrapped in try/catch so one bad row drops instead of crashing.
- **`appendLog` / error boundary** — made total and now log instead of bubbling.
